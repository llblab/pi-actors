# Actor Inspector

Open the live owner-filtered Run browser with:

```text
/actor-inspector
```

The Inspector follows the kernel directly. It shows Runs owned by the current Pi session and offers exactly three tabs.

Presentation follows the project-wide [Agent Experience (AX) standard](./agent-experience.md): Recipe, Control, all Trace-detail metadata and captured Kill fields use real block YAML. Agent-turn detail keeps selected text/Markdown outside metadata without added outer indentation; feedback messages remain literal selected text. Readable tables still serve comparison and navigation. Preserve chronological ranks, ids, source order, focus, selection, keyboard navigation and privacy; machine Trace JSON is unchanged, and source/headless checks are not authorized live terminal/phone acceptance.

## Document and detail layout

Every metadata document shares the same YAML 1.2/core encoder. Mappings use `key: value`, nested collections use two-space indentation, and `-` introduces only real sequence members; no synthetic `item` key is inserted. Scalar types, singleton sequences and empty `[]`/`{}` retain their shapes. Unknown or ambiguous keys/strings are safely quoted. Process stdout/stderr tails and other non-agent selected strings are YAML scalar data, using literal or quoted forms that preserve decoded CRLF, blanks, trailing spaces, headings, lists, apparent headers and code fences exactly. Their contents never become extra fields, Markdown bodies or actions.

Long YAML lines and paths wrap by native terminal-column/grapheme rules without cosmetic clipping. Preferred separator breaks keep original spaces/slashes/commas; soft continuation creates no omission marker. The existing two-space terminal tab policy remains display-only. Narrow soft-wrapped frames are not claimed to be independently parseable YAML; strict shape/value round-trips apply before terminal wrapping. Root fields serialize separately to preserve their stripe ownership across nested and wrapped lines. Source values/journals, scroll/focus/selection/IDs/ranks/source/privacy/body budgets and public JSON stay unchanged. Complete overlay scenarios and literal/Unicode/stripe properties belong to the source and installed compiled owners; loaded colored-terminal/phone acceptance remains separate.

### Agent turns and tool steps

Opened `agent.turn` detail separates literal YAML metadata from independent native Markdown bodies for selected assistant/user/thinking text and tool-result text blocks. Each body begins at the left content edge, with no added horizontal/vertical component padding, code-block gutter, nested `assistantText`/`result` scalar or whole-body fence. Authored list/code/YAML indentation remains in the exact renderer input; Markdown interprets its own visual syntax. One unfinished fence cannot consume a later body or metadata header. Source-authored JSON, YAML, comments and apparent action/header labels remain content, never parsed into metadata or actions.

Root metadata and non-text result parts remain YAML block mappings/sequences. Metadata-only fragments are bare; a separate body's field-path header has opening/closing `---`. Field paths identify selected display slots; numeric components are array positions, not event identities or chronological ranks. Present selected undefined values remain visible as UI-only `value_state: undefined` records, distinct from null, literal text and absent optional fields. These records do not alter saved data or certify source availability. Existing source selection/redaction, budgets, unknown fields, usage, arguments, error facts, stripes, paging, selection and action fences remain unchanged. The shared metadata encoder also serves other Inspector documents; this does not update an already loaded extension. Compiled/installed parity and permitted live/phone acceptance remain separate boundaries.

## Recipe

Shows captured execution provenance:

- file-derived Recipe stem and logical reference;
- source kind (`user_registry_capability`, `active_skill_component`, or `explicit_file_recipe`) and Skill identity when owned;
- resolved template and values;
- root/import roles plus alias ancestry;
- declared artifacts and actor-local actions;
- model/thinking policy and launch source.

Captured Recipe evidence belongs to the Run generation and does not change when an active Recipe file later changes. Skill components display logical identities such as `artifacts/report`; private physical `source_file`, `skill_dir`, and `recipe_dir` stay out of Inspector and model-facing views. Document fields render as YAML mappings, nesting only for actual objects/sequences. A singleton action remains a sequence; a complex sequence element is its original mapping, not an `item` wrapper or a synthetic #0 identity. Empty []/{} distinguish empty containers; null and selected undefined display states remain distinct. Existing provenance selection and privacy are unchanged.

## Trace

Shows the unified bounded Trace projection. Sources include lifecycle/runtime observations, Controls, owned Pi turns, command-log tails, results, artifacts, and diagnostics. The source selector displays only `all` plus sources present in the current projection from `lifecycle`, `control`, `process`, `agent`, `artifact`, and `runtime`. Select a row to open structured detail.

Trace ordering stays deterministic and newest-first: timestamp descending, same-source physical ordinal descending, fixed internal source rank, then stable id. The list now uses shared chronological ranks `#N`, `#N−1`, … from recorded-observation metadata before source/display clipping, not current-view positions. Filtering selects from that same basis and may leave gaps; scrolling never restarts it. Another later retained event advances the newest rank beyond the 100-row source/display tail. The numbers describe recorded chronology, not a lifetime count or persistent event identity; this context is available in row detail rather than a standing first-row explanation. Known missing history, unavailable/private/missing-time metadata, unsupported coverage, duplicate keys, index overflow or inconsistent legacy equal-time ordering gives `#?`, with its reason in detail rather than a guessed offset. Detail retains id/provenance and original `projection_sequence` (including zero) and adds UI-only `chronology`; public Trace JSON/canonical event schemas stay unchanged. Source sequences may repeat and prove no cross-source causality. Terminal/result/execution/artifact evidence retains its separate authority; path/redaction/body limits and id-based selection remain unchanged.

Trace rows are one-physical-line previews: native terminal-column clipping and retained newlines show a visible … at the actual display gap, while opening the row retains the same full already-projected item/detail. Short rows gain no synthetic gap and authored ellipses remain literal. This does not disclose raw/private tail lengths, change source omission counters or promise unretained source text. A real incomplete-history warning stays visible (Trace incomplete… at narrow width). Routine numbering/explanation banners are absent; #? still marks unavailable numbering, with the reason in existing detail. The selected Trace triangle starts at the left content edge without an added gutter; unselected ranks stay aligned. Error rows no longer add a redundant ! after the rank: the existing source/kind, error coloring, summary and detail remain. Non-attention rows reserve no empty marker column; the existing non-error attention A stays visible where applicable. Authored exclamation marks are content, not removed. This removes display noise without guessing history or hiding actual loss. This is limited to Trace table layout; aligned Run selector, source/rank/order/filter/selection/cache/scroll/stripes and public JSON are unchanged.

Trace items and the lazily read journal warning summary share the current per-Run/generation overlay cache. Arrow/page/filter/detail/resize navigation reuses that snapshot instead of reopening/reparsing trace.jsonl on each render. Explicit invalidation, Run/generation changes and the existing one-second refresh invalidate the cache; a new incomplete-history warning appears after the next refresh. This is read-local caching, not immutability, fresh native proof or a promise of measured live frame latency.

Agent Trace ids now bind recorded entry provenance rather than aggregate traversal position. Native keys include the recorded session header, entry/role and command/file namespace after the existing manual projection's metadata privacy checks; their public spelling is opaque. Growth in a sibling session or manifest reorder no longer changes an unchanged native entry's key, so existing id-based selection remains on that entry. A changed admitted session-header identifier changes the key. Empty/duplicate/missing-header or degraded/private entry metadata falls back to an admitted parsed-record position, not a promise of permanent identity; a privacy-changed namespace has only read-local legacy identity. Hidden raw values and bodies are not digest inputs. Missing-id records and oversized files retain their existing refusal behavior. This does not certify source immutability, original producer privacy, active session/work authority or absolute chronological numbering.

### Chronological numbering: requested replacement

The requested replacement is one mixed-source chronology whose newer events have higher numbers: newest-first `#100`, `#99`, …, `#1`; another later event advances to `#101`. Filtering selects that same numbered chronology, so gaps may be visible, and scrolling does not restart numbering. The bounded recorded-observation implementation now replaces the superseded positional `#1…N` list. It deliberately does not claim complete original lifetime numbering when history is missing or source provenance is unproven.

The existing projection is not a complete append-only event stream:

- The per-source collection cap is 100 before the overall display cap. A canonical journal with 102 retained events still yields 100 projected canonical rows even with `limit: 200`; its latest source sequence advances while array length does not. Reversing that array cannot provide a lifetime ordinal.
- Process stdout/stderr rows are mutable observations with fixed ids and timestamps derived from current file metadata. Updating one stream can move that same id across other events without appending a canonical event. Artifact observations have the same snapshot-versus-event distinction.
- A newly retained event may have an older timestamp. Existing append/source order then differs from chronological display order. A recomputed chronological rank can change for an already known id; it must not be mistaken for an immutable event identifier.
- Canonical compaction/read-loss evidence, bounded session turns and missing legacy history do not provide one complete mixed-source chronological prefix. A source-local counter or a snapshot DTO cannot recover missing global positions.

The implemented common basis collects bounded scalar metadata before source/body/display clipping, with explicit coverage/unavailability. Canonical and Control keys/times come from their already bounded reads; Control input/error projection is not expanded, and previously observed process/artifact snapshots are reused without extra target probes. Eligible pre-tail session entries use the identical opaque agent identity helper as body rows. The metadata key array is bounded by the existing4MiB Trace limit, independently of the unchanged body/display caps. Validation confirms canonical101→102 with100 visible rows, mixed metadata205 with200 displayed rows, source-filter gaps, old source-sequence detail, late/mutable rank changes, UTF8 metadata overflow and equal-time ambiguity. Some legacy same-source/cross-source tie relationships are not a total order: if the metadata rank cannot preserve all existing all/source-specific presentation orders, numbering is unavailable rather than changing that ordering. Keep existing body permissions and budgets; do not publish additional bodies, synthesize events during a read or add a persistent numbering service by implication. Use the existing timestamp/tie ordering as presentation, not proof of cross-runtime causality. Lifetime numbering across unavailable history remains unproven; do not silently label a retained-window count as an exact absolute event number. Stable producer identity and recomputable chronological display rank remain separate responsibilities. The owned projection/overlay properties and actual npm compiled replay now exercise the bounded implementation and those rejection boundaries. Live colored-terminal/phone acceptance and an operator-authorized extension reload remain separate; headless render checks are not that acceptance.

#### Pre-tail session metadata: internal prerequisite

The session reader now retains a frozen non-JSON metadata frame before its 100-turn body tail. Execution-session collection carries that data through the existing source-reference admission fence, including per-file and aggregate source ordinals and admitted command/file namespace. A 101-turn source can therefore supply 101 metadata entries while still returning only its original 100 body turns; two sources with 101 + 1 turns provide 102 metadata entries and 101 body turns. No second body reader or persistent index is added.

The frames contain only eligible entry provenance and existing canonical stored timestamps, not body/thinking/tool/usage text or newly sampled time. Each frame and the aggregate have a separate UTF-8 encoded metadata budget no greater than the existing 4MiB session-source bound; this is not a larger body/file/model allowance or a work quota. Private/ambiguous identities or namespace, unavailable/missing time, malformed source/schema, known source loss/change and overflow produce an unavailable frame without a partial index. Existing body refusal, redaction, return shape, diagnostics and limits stay unchanged. Source aliases and replacement refuse metadata under the same existing fences as bodies. Available describes the selected recorded metadata only, not original producer privacy, authentic issuer, immutable bytes, a complete lifetime prefix or an active epoch.

These frames remain inputs, not independent ranking/permission certificates. The shared Trace owner now joins them with canonical/Control/current-snapshot metadata before clipping; the Inspector consumes the resulting read-local rank or explicit unavailability. Duplicate keys, late/equal timestamps and missing-history coverage are checked separately. No persistent numbering service, immutable event-number promise, new source-body allowance or live rendered acceptance follows from this implementation.

## Control

Control is a read-only view of what the selected Actor declares and what happened to recorded requests, not a chat, a universal pause/resume interface or a new command sender.

The overview starts with the whole selected Run identity and explains:

- Actor-control readiness: no declared actions, declared but no matching recorded endpoint, recorded endpoint ready, full pending capacity, or unavailable/partial data.
- The declared actor actions and existing runtime API capabilities. Only the existing Run-focus Kill remains interactive; archive/prune are informational here.
- Queue counts, journal size/diagnostics and bounded history coverage. Unavailable data never becomes a healthy empty queue. A nonregular journal source is unavailable even at reported size0; only actual absence or an empty regular file permits a healthy empty history.

Readiness uses existing metadata/journal owners and requires the selected Run, owner and generation to match. A matching `control-endpoint.json` is recorded readiness only, not a successful connection, fresh process-identity or actuation proof. Malformed/unreadable data, refused records, foreign generations and duplicate IDs are diagnosed conservatively. Known safe rows may remain visible with partial coverage; replacement actions/history are withheld when the metadata binding is unavailable.

Enter on the Control tab opens recent requests; Down enters the scrollable YAML overview, whose Enter opens the same request list. Requests use Up/Down or PgUp/PgDn selection; Enter/Right opens full projected YAML and Left/Esc returns. Rows put the actual status first so a long action cannot hide it, then action, age since its recorded status timestamp and a clipped first-line error or stale reason. Detail retains only recorded timestamps and redacted input/error. No missing delivery/claim/handling stage is invented: delivered does not mean handled, and handled does not mean the Run completed.

The list is the newest suffix of at most20parsed journal records, reversed for browsing—not a complete lifetime or timestamp-sorted history. Malformed JSON lines are omitted by the existing reader, diagnosed separately and make coverage partial; this is not a20-physical-line window. Shown/retained parsed counts and partial coverage remain explicit. Selection uses the exact Run/generation/raw request ID; refresh preserves that identity, while disappearance or generation replacement makes detail unavailable instead of silently rebinding it. Overview/list/detail share a read-local observation under the existing one-second invalidation; keyboard/resize navigation does not repeatedly read the journal, and Control navigation does not read Trace.

Capacity reaches zero at64pending Controls. Admitted requests never expire automatically: a five-minute stale-age marker is an observation, not a failed transition, native/work duration or permission to retry. The durable `controls.jsonl` stays raw and local; rendering neither mutates it nor exposes a second unredacted copy. Source/headless, compiled and independent-review evidence remain separate from an authorized reload and actual terminal/phone acceptance.

## Focus and Selectors

`selectedBg` marks the current focus or selection; `customMessageBg` remains reserved for alternating content stripes. Opening the Run or Trace-source selector preserves `selectedBg` on its parent control, so focus reads as parent → child menu → selected option. Menus are composited over only their bounded rectangle; base content before, beside, and below that rectangle remains rendered.

The Run dropdown starts five content columns from the left edge (one column farther right than its original placement). It retains the compact leading marker and now reserves one explicit internal padding cell on the right, including after clipped text or an ellipsis. Its own alternating backgrounds follow absolute option indices, not the underlying document rows or the scrolled viewport. Both borders reset the background; native clipping resets are repainted inside selected/striped rows, including ellipses. The Trace-source menu keeps its earlier geometry and styling. These are terminal cells, not pixel offsets.

The Run selector uses aligned zero-based list rank, Run name, and semantic status columns. Its #N is a position in the current cached Run list, not a stable Run identity or authenticated lifetime chronology. The Trace selector uses `Trace: <source>`; when a non-`all` source is active, the tab projects the same colon grammar and value color.

Run header and Run option previews now apply producer-specific native column budgets and a visible ellipsis only at a real display gap, before unchanged generic fitting/composition. A cropped label/#rank is not a complete identity. The whole already-selected logical name appears as selected_run_id at the start of the existing read-only Recipe and Control documents; use ordinary Enter/scroll/PgUp/PgDn there, never Kill confirmation for identity research. The compiler-selected context field is projected separately from authored content, so a matching authored key cannot replace it. No new key, reader, source permission or action is added. Selection/cancel/resize/cache/order/status colors and exact original action targets/generations remain unchanged. The [initial counterexample](run-supervision.md#run-control-and-selector-convergence-assessment) is retained as historical evidence; the [correction](run-supervision.md#run-control-gaps-and-read-only-selected-identity) is source/npm/headless validated, not loaded colored-terminal/phone acceptance.

## Feedback popups

Routine feedback appears as the complete already-selected text in a compact Notice popup above the Inspector and any open selector. There is no synthetic i: prefix, i command, feedback field wrapper or secondary reader. Authored paragraphs, blank lines, indentation, colon labels, lists and backticks remain literal content through native-column wrapping. No source tail or discarded cause is reconstructed.

Esc is the notification's only dismissal action. Action, confirmation, tab and source keys cannot reach underlying work while the popup is open. If the complete text physically exceeds the available rectangle, Up/Down and PgUp/PgDn scroll it inside that same popup with a visible line range; there is no separate details mode. Small messages show all text immediately and only the Esc hint. Ctrl-C retains global close behavior. Esc clears the transient feedback rather than retaining an i history.

Both notification and Kill dialogs have a two-terminal-column left inset for content and one blank row above and below it. Their borders use borderAccent; keys use accent, descriptions use borderAccent and hint groups are separated by borderAccent frame segments, through the same formatter as the main Inspector. On the lowest available height, decorative blank rows yield to readable text, pinned safety and choices. Narrow confirmations may stack the two choices and wrap the pinned warning rather than clipping either. Both dialogs use the terminal's default background, not a pale theme fill or hard-coded black. Borders and foreground status colors remain; selected confirmation buttons retain their focus background. Popup composition masks only its own rectangle and never inserts a data row or shifts the document, stripes, selection or scroll. The last normal Inspector frame is frozen underneath the modal; resizing reuses those captured cells without new evidence reads. Closing resumes normal rendering/invalidation, not a renewed ownership/native guarantee.

Only feedback from the existing Kill callback path pins closure: unconfirmed and No automatic retry outside the popup's scrollable text. This records entry into an action-port path, not native actuation or proven no effects. Local guards do not gain those action uncertainty labels. Routine cancellation is silent: Esc/n or Enter on Cancel closes the confirmation and immediately returns to the same Inspector, without a Notice or an extra dismissal. The popup exposes only the existing selected message, not raw Error/cause or lost180/160-unit tails. Fresh Kill producers now wrap selected values in AX action/result/state-or-diagnostic/closure records. Domain180-unit normalization/trim and overlay160-unit normalization/slice remain the source stages; their already discarded Markdown/tails/causes are not recovered. A pair crossing the prefix end retracts one code unit; a malformed selected preview is unavailable with unknown loss rather than repaired text. Dynamic legacy previews state unproven upstream completeness/privacy, never an exact private-tail count. Compiler refusals add no invented legacy omission. Message/result shape and actuation stay unchanged; saved journals are not rewritten. Source/installed tests cover full opaque access, narrow columns/low rows, scroll/return/selector behavior, no action replay, original Error.message observation and unchanged selected caught-error bytes. Actual operator-loaded colored-terminal/phone acceptance remains separate.

## Kill confirmation

Kill confirmation is a compact popup, at most72terminal columns including borders, composited and centered over the Inspector rather than replacing its screen. Its height follows the wrapped captured content, with parent chrome left visible instead of filler rows. At narrow widths it uses the available width. It presents captured run/state/action as block YAML using the shared metadata document renderer. The selected Run name is displayed without a redundant namespace; the original captured run/generation still goes unchanged to the existing generation-fenced action port. At narrow widths or low terminal heights, PgUp/PgDn pages only those descriptive fields and a visible range explains the available pages. The full captured identity remains accessible, not silently shortened. It is captured evidence, not a fresh status read or new permission.

Both Cancel/Kill choices and closure: unconfirmed stay pinned outside that field viewport. One blank row separates the closure note from the choices, including narrow layouts with stacked buttons. Cancel remains the default. Arrow/Tab selects a choice, Enter applies that choice, y invokes the original Kill action directly, and Esc/n cancels. Paging or resizing never invokes the action or changes the selected choice. Narrow footer hints are compact; a paging hint appears only when fields overflow. Whole-source/installed tests cover widths24/52/90/140 and terminal10/12/30rows, complete captured-name reconstruction, pinned safety/buttons, default cancel, choice/reset/resize, exact original generation and once-only callback. An additional compactness/centering property covers terminal10/12/30/80rows across those widths without actuation; long captured-field paging remains covered separately. This is headless source/npm evidence, not live colored-terminal/phone acceptance or native scope-closure proof. Fresh Kill feedback now uses AX around the original loss-bounded selected preview; this is not fuller error retention or native closure proof.

## Keys

The footer is authoritative for the current focus. The stable navigation contract is:

| Focus | Keys |
| --- | --- |
| Run control | `←`/`→` change Run, `↓` enters tabs, `Enter` opens the Run selector, `k` requests kill when available |
| Tabs | `←`/`→` or `Tab` changes tab, `↑` returns to Run, `↓` enters content; `Enter` opens Recipe content, the Trace-source selector or Control requests |
| Trace tab | `f` cycles present sources without opening the selector |
| List/document/detail | `↑`/`↓` and `PgUp`/`PgDn` navigate; `→`/`Enter` opens a Trace/request row; `←` or `Esc` moves back |
| Control overview | `↑↓`/`PgUp`/`PgDn` scroll; `Enter` opens requests; `←`/`Esc` returns to tabs |
| Selector | `↑`/`↓` chooses, `Enter`/`→` applies, `←`/`Esc` cancels |
| Kill confirmation | `←`/`→`/`Tab` choose; `Enter` pick, `y` Kill; `Esc`/`n` cancel; `PgUp`/`PgDn` fields |
| Notice popup | `Esc` dismisses; only physical overflow uses `↑↓`/`PgUp`/`PgDn` within the same popup; other action keys are ignored |
| Overlay | `Esc` closes from the top level when no modal is open; `Ctrl-C` closes immediately |

Run kill revalidates owner and generation through the canonical lifecycle path. After success, the selected Run status header is the sole UI confirmation; no success Notice or duplicate content is added. Cancel likewise only closes the dialog, without invoking Kill or opening another popup. Refusals, errors and uncertain action results remain visible; this local suppression does not remove notifications on other surfaces where the result is not directly visible, or turn status into whole-scope closure proof. The Inspector never edits state directly and never derives authority from displayed data.

## Scope

The Actor Inspector treats each Run as a concrete actor instance. It does not expose group conversations, peer addresses, routing, or communication topology. Use `inspect target=runtime view=status|runs|triage`, `inspect target=recipes view=status|summary|doctor|imports|reviews`, and `inspect target=tool:<name> view=status|schema` for non-Run management targets. See [Management Inspection](./inspection.md) for exact applicability and authorization boundaries.
