# Runtime Output Projection Map

Status: F1.1 source ownership audit, updated for the F1.2 helper and F1.3a1 compact launch migration on candidate `16a3417` and the retained working tree. This map is not production migration, live UI/native acceptance or default activation proof. The [AX contract](agent-experience.md#document-envelope-and-yaml-syntax) owns the adopted format; [BACKLOG.md](../BACKLOG.md) alone owns remaining work. Line references are navigation anchors for this audited source, not permanent identities.

## Reading the Map

- **Runtime metadata:** Target is native block YAML, bare when there is no separately selected body. A body-bearing document has `---` above/below its metadata, followed by unchanged selected text/Markdown. Tool synchrony does not choose framing.
- **Selected content:** Actor reports, stdout/stderr excerpts, literal requested sources and opaque advice/diagnostics are not objects to parse and reserialize. Preserve their existing selection/privacy/clipping basis; do not promise recovery of discarded upstream bytes.
- **Machine data:** SDK/Recipe inputs, `details`, canonical journals, inventories, fingerprints and helper protocols keep their machine formats. A runtime-generated readable view of those facts is a separate YAML projection.
- **UI chrome:** Selection, columns, stripes, modal choices, animation and paging are not serialization formats. Owned metadata documents are in scope; changing their appearance must preserve their native UI behavior.

```text
JSON arguments -> SDK/context/admission/execution owners
  -> selected facts/details -> owned tool text -> host tool result
  -> selected producer text -------------------> opaque body

Terminal observation -> frozen completion/attention capture
  -> budgeted text + compiler frame/hints -> Pi delivery
  -> stored acceptance/recovery + compact/expanded renderer
```

## Dependency Facts, Not a Second Work Plan

Bare tool receipts can be addressed in their projection owners without redefining Run execution. Completion changes are coupled across byte fitting, frozen capture compatibility, nested-header validation, whole-node hiding, compiler ranges and stripped-details recovery. Service-carrier replacement has a further evidence gate. There is no safe global `JSON.stringify` or `formatMarkdownField` replacement: both cross metadata, source, historical replay and machine-data boundaries. Remaining implementation and acceptance are tracked only by F1 in `BACKLOG.md`.
