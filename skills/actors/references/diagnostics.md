# Diagnostics

Preserve the intended logical identity and diagnose through public pi-actors surfaces. Do not inspect raw registry files or implementation source as the normal first response.

## Recipe resolution or catalog failure

```text
inspect target=recipes view=status
inspect target=recipes view=summary
inspect target=recipes view=doctor identity=<skill>/<recipe>
```

`summary` and `registry` name the same inspection path: identical facts, details and rendering for identical `verbose` input, so only `verbose` selects compact text versus structured output. The compact label still reports `recipes: registry`, and that label is not a separate view to request. Unsupported-view refusals list the actual accepted view names.

Compact Recipe/Run/tool replies use flat AX fields without changing their existing evidence or authorization. Required/optional tool arguments are sequences, with none distinct from unknown. Focused source_location remains one exact literal value. Run compact replies still identify only run/view: request verbose for structured evidence, and tool schema remains structured even without verbose. Compact text selects at most one existing hint; only exact read-only recipes doctor/imports/summary inspection literals become typed next nodes. Other advice stays instruction content with its original Markdown, never executable metadata or authority to rerun work/register a tool. The full original next_actions array remains in details; do not infer callability from an advisory string.

Use the focused doctor form for one intended identity. It reports active-Skill ownership, exact resolvability, partial-catalog state, component status, portable source location, resolution generation, any rejection, and bounded next actions. Use the unfiltered doctor only for catalog-wide diagnosis. A partial catalog does not imply every exact component is unavailable. If the owning Skill is inactive, report that blocker rather than locating and running its helper manually.

## Inspection request refusals

Locally authored target/view/identity/source/tool/schema refusals now show AX fields and actual supported-value lists. target_kind identifies only the selector family; no ownership, no-effects or native claim follows. A missing tool retains the no-spawn-substitution safety note and a read-only Recipe doctor next. Unavailable callable schema preserves selected callability/activation facts and one read-only tool-status next. Generic syntax/view guards add no routine action. An oversized selected scalar/action is omitted whole with shown/omitted/total counts under the shared16KiB text bound; those counts cover fields/actions, not hidden text length. A next_action omission record is not an executable next node. Opaque multiline labels are not parsed into commands.

This applies only to errors authored by inspect itself. Session/scope/source/dependency errors retain their owning contract and original propagated values/causes; existing fail-soft catches are unchanged. Discovery/status callbacks may already have run before a refusal. Diagnose through the original owning surface rather than treating an error as proof of no effects or retry permission.

## Control request guards

Locally authored unsupported runtime action, unavailable runtime port, unavailable Run generation and undeclared actor-local action errors now identify caller target/action/result and actual supported_actions/available_actions lists. A singleton remains a list; none differs from an explicitly omitted group. These are diagnostic options, not a command, readiness proof, native receipt or automatic replay instruction. Whole target/list groups fit16KiB including public spacing or have explicit selected-field/entry omission coverage; malformed selected text is unavailable without source repair or hidden character counts.

This does not restyle normalizer/session/scope/dependency failures, expose status/input/owner/generation/correlation or change the existing actor-local awaited-send error boundary. Status/getter/legacy join observations can fail before a local diagnostic; runtime callbacks can throw after effects. Preserve those original exceptions and diagnose the existing owner rather than broadening a catch or assuming no effects.

## Spawn request guards

The facade's own unsupported state_dir and invalid as errors use field/result records; as is selected caller input, not an admitted Run or generation. Namespace/id refusals show accepted_format and, for invalid ids, the existing ASCII character rule. Whole values fit16KiB including spacing or are explicitly omitted; malformed selected text is unavailable without repair or hidden character counts. Opaque multiline value labels are not actions, and no routine next/retry/no-effects receipt follows.

The actual host clones/validates public arguments first. Its unchanged schema rejects unsupported state_dir before the facade and keeps the SDK's own validation text; do not bypass that boundary to obtain AX. Direct facade getter/method/coercion failures, Recipe/session/launch/draft errors and post-launch effects keep their original owners and behavior.

## Persistent tool failure

```text
inspect target=tool:<name> view=status
inspect target=tool:<name> view=schema
```

Successful normal register/update-or-persisted text now separates tool/result/source/callable_now, lists required/optional args and warnings, and keeps one prior hint. Non-template source references are whole literals; safety warnings take budget priority. Whole selected fields/groups/actions fit16KiB or carry omission counts; malformed selections are unavailable without repair or hidden character counts. Invocation advice is opaque instruction rather than an automatic call. The unverified branch retains one typed read-only tool-status next; all existing next_actions/details remain. Post-persistence callbacks/formatting can still fail with their original values, so text does not add rollback, fresh activation or retry guarantees. List/delete/draft/transaction errors and notices remain separate.

Listing returns the original current Map's sorted names with selected-name coverage. The entire selected group is shown or explicitly omitted/unavailable within16KiB; none means the selected list is actually empty. This is not active-tool/callability, complete-host or lifetime inventory evidence. Delete returns tool/result with the original manual reload note as opaque instruction. A missing current-map entry does not delete an orphan recipe file or prove no effects; a returned deletion is not complete loaded-registry removal. Do not reload or repeat automatically to change that presentation. Errors after unlink/map/active-set/notify effects keep their original values, without a new wrapper/rollback.

Draft-promotion success now uses selected tool/result/source=draft/callable display and the first prior hint, without adding undisplayed args/defaults/path/body or activation-boundary facts. Existing zero/opaque display and later getter disagreement are not repaired into a new Boolean/readiness claim. Scalar/action fields are whole within16KiB or explicitly omitted/unavailable. Only the producer's exact canonical tool-status hint is typed read-only; invocation advice stays instruction. Original display conversion may still fail after persistence/map/activation/notify effects, including Symbol or unprintable values; preserve that failure rather than replaying or importing normal-registration rollback behavior.

Four local source-mode refusals now show field/result plus replacement fields, accepted reference forms, mutually exclusive source modes or inherited args/async fields. Previous repair advice remains opaque instruction; it is not a typed mutating retry/update or no-effects proof. These fixed diagnostics neither echo source values nor restyle normalization/resolution/admission/transaction failures. Outer name locks may already have observations before a local error.

The host first clones/coerces/validates args. It rejects unsupported values/object-valued from before execute, but numeric from can normalize to a string; an unnamed valid request can still return the existing name list. Direct getter/descriptor/trim probes are not SDK-cloned DTOs. Do not override schema or force a public error solely to obtain AX text, and do not infer the caller's original type from post-validation data.

Ordinary invalid-name, reserved-name and new-registration missing-source errors now use field/value/result or a real source-mode sequence with prior opaque repair advice. No raw caller name/source/body is newly exposed. Reserved selected display fits whole16KiB including spacing or has scalar omission/unavailability; this is not hidden character loss or ownership/invocation proof. Empty-name listing and existing-tool update reusing source remain unchanged. Normalizer/reserved-set/resolution/authoritative/blocker exceptions retain original behavior; a dependency blocker is not reformatted as an owned refusal. SDK numeric name coercion may reach a different local guard than the direct request, while object-type schema rejection stays outside execute. Both ordinary and draft already-registered errors now use field/value/result with exact Use update=true to overwrite instruction content. Distinct Map/authoritative-file/exists/blocker/update checks remain; the selected display does not disclose source/recipe bytes or certify no effects, rollback, fresh host membership or overwrite permission. Whole scalar omission/unavailability and raw observation/coercion failures remain explicit and unchanged, respectively. Nested Recipe-shaped template, empty sequence and unsupported template type now have fixed template/result AX errors and real supported-type choices, retaining prior correction as opaque instruction without supplied body/source echo. External expansion/getter failures stay raw. Front null/empty deletion, undefined/inherited source and later authoring errors are not reclassified; a numeric SDK template may be coerced to a command string rather than reaching the direct unsupported-type refusal. Later non-object defaults, missing command description, authoring-stage null and missing final template now use fixed field/result without supplied values. Preserve the error's actual stage rather than treating null globally invalid or every missing source as a late template failure: host defaults schema rejection, front deletion and earlier missing-source refusal still precede or bypass these guards. Schema argument/description/default/retained-template observation faults keep their original owner and values. The delegated-source runtime-owned-default-key refusal now names the old first selected key only with fixed defaults/result and opaque remove-default/retry advice. Key order and complete prior default copy remain; do not infer a complete key listing, supplied values, early effect-free rejection, global command-template ban or permission to repeat. Host SDK preserves selected-key error normalization without granting readiness or overwrite authority. Draft outside-root/current-not-found diagnostics now identify field draft and only the original allowed-root/resolved-path literal; root refusal does not add the refused caller path. Whole references fit16KiB or are explicitly omitted/unavailable without repair/private counts. Old summary hint stays instruction content, not an automatic call/listing guarantee. Getter/resolve/relative/dot-prefix/exists behavior and raw faults remain; not-found text is not stronger absence/native/host proof. Public from-normalization wrapper now reports only original displayed source/reason/legacy active_skills_summary and opaque doctor instruction, with whole-field omissions/unavailability under16KiB. Inner normalizer errors, Error.message.trim/String and old display/summary/doctor observation order remain. Do not parse comma summary/body Next labels, infer discarded counts/private causes, fix undefined/source-hint disagreement or automatically execute advice; other validation/transaction errors stay separate. Draft invalid-Recipe raw/candidate refusals now likewise use fixed draft/result plus old optional reason or joined diagnostics only, not new paths/bodies/causes. Separate raw read/diagnose calls, reason truthiness, original draft Error-before-join timing and upstream4096UTF16 candidate cap stay unchanged; malformed selected text is unavailable without repair. This neither merges normal/draft policy nor proves no effects/rollback or authorizes retry. Distinguish persistence, registry admission, host registration, active-tool membership, and `callable_now`. Confirm the source identity, effective caller schema, separate tool/spawn usage, and last launch kind when exposed.

If persistence succeeded but callability is false, do not use `spawn` and claim the tool worked. Follow the reported activation boundary or stop.

## Run failure

```text
inspect target=run:<id> view=recipe
inspect target=run:<id> view=trace
inspect target=run:<id> view=control
inspect target=runtime view=status
```

Use Recipe view for captured identity/launch evidence, Trace for bounded observations, Control for readiness/capacity/stale work, and runtime status for kernel-level health. Treat retained-history completeness honestly.

Compact runtime replies now use flat runtime/status, runtime/runs or runtime/triage records from the same existing facts. runs counts the full current-owner inventory, not a display page; verbose file navigation has its own independent bounds. Triage scalar counts need not equal its40displayed detail rows. This is not a new Run status/snapshot, duration, body source or routine polling route. Core callback errors keep their diagnostic content and original error forwarding. Completion recovery reports the original pending/evidence/reason without forcing resend; an idle batch shows delivery accepted only after durable acceptance, not as proof of model handling. Teardown killed/failed/skipped/discovery counts and a whole literal summary path are a teardown report, not whole-scope closure. Stored packet/history text is not regenerated.

## Watcher and automatic retirement notices

Watcher diagnostics use watcher/scope/path/diagnostic/recovery records. Exact paths are literal values, not commands or body permission. Degradation preserves the existing reconciliation/rearm guidance; rearmed reports restored acceleration only. IDs/timestamps/code/scope and bounded history are unchanged, not complete lifetime evidence. Diagnostic bodies are opaque, including apparent next/tool labels.

Automatic retirement reports stop request returned, cancellation reported, skip or failure, with closure unconfirmed. Neither a returned callback nor a truthy cancellation report proves owned-scope termination. stop path failed includes notification failure after earlier stop/cancel effects; do not blindly replay work or infer no actuation. Candidate/attempt/callback/result/error behavior and lower-layer information loss remain unchanged. This is separate from manual archive/prune, native closure and actual lifecycle receipts.

## Safe failure protocol

1. Keep the exact intended Recipe/tool/Run identity.
2. Identify the owning public surface.
3. Record exact resolver, registry, activation, or Run truth.
4. Apply only the bounded next action returned by that owner.
5. Retry only after the owning state is healthy.

Stop if evidence remains contradictory or the requested operation cannot be proven. Never recover by copying maintained contracts, hard-coding installation paths, directly executing bundled helpers, adding `bash -lc` or `eval`, shell-backgrounding work, editing unrelated Skills, or relabeling a Recipe spawn as a tool call.
